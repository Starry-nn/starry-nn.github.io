PROFILE STUDIO / BEGINNER GUIDE

Your profile.
A layout to start with.

Choose a layout, add your own details, then use an Agent or copy the README yourself. You do not need to write code to use the forms.

Open the editor ↗
A GitHub profile README, not a separate website.

This tool creates README.md, an introduction shown on your GitHub profile. It does not create a GitHub Pages website, log you in, receive tokens or publish directly. Alex Builder is a fictional example.

Choose a layout and make it yours

  1. Pick a template card.

    Use Show all to see more styles, or search for portfolio, terminal or typing layouts. Preview changes immediately.

  2. Choose where your details come from.

    Let my Agent fill in my details is enabled initially. Your Agent replaces unspecified example identity fields with verified public information at publishing time. Manually edited fields are kept. You can also import public details directly from GitHub.

  3. Add only what you need.

    Expand Profile details or More about you. Add projects, open-source contributions, writing & resources, custom sections and links. Each collection supports up to 30 entries, ordering, removal and undo of the last deletion. Empty optional sections are omitted. Use contributions for repository, PR or Issue links, and writing for articles or tutorials. Search skill tags by topic (AI, frontend, data), click suggestions or press Enter for a custom tag (up to 15). Work and education are no longer form sections; legacy data stays in local drafts.

  4. Check the layout.

    Change header, skills and project presentation in Layout and components. Reorder or hide sections, and check Dark preview. On a phone, Edit details jumps to the forms. In Free edit, the source—not the form layout controls—is authoritative.

The EN / 中文 switch changes the interface, help and Agent instructions. It does not translate your personal content. Drafts are saved in this browser only; download a backup before changing devices or clearing browser data.

Import public details and select repositories

  1. Click Import from GitHub.

    Enter a username, GitHub profile URL or repository URL and click Load profile and projects. This is a public lookup, not sign-in or proof of account ownership. Private repositories are not accessed.

  2. Search and select projects.

    Repositories and website entries inside GitHub Pages repositories appear separately. Entries are detected from index.html paths; verify live URLs. Search the loaded items and tick the projects you want. Load more repositories fetches another page when available. Forks and archived repositories are labelled. Selection survives searching and loading more pages.

  3. Review and confirm.

    The selected projects are appended with repository names, descriptions and full clickable GitHub URLs. Existing projects stay intact and duplicate URLs are skipped. The optional public-profile checkbox fills name, bio and website without replacing manually edited fields. Repository languages are technology labels, not proficiency claims. Employment or education is never inferred.

For a non-GitHub project or a private repository, use the manual project field: enter a repository name or full project URL. A bare repository name uses the profile username; a full URL preserves the exact destination. A project without a URL is shown as text, never linked to an invented repository.

LinkedIn, X, Hugging Face and YouTube accept a supported handle or full URL. Google Scholar and Other require a full URL. Other also lets you choose the link label. Only safe HTTP(S) URLs become clickable links.

If GitHub is unavailable

Public API requests may be rate-limited or fail. Retry later or enter full project URLs manually. The website does not request a token to bypass this. An Agent still verifies its own authenticated GitHub account before publishing.

API behavior follows GitHub’s public repository documentation ↗.

Option one: use your Agent

  1. Click Hand off to Agent.

    Select Codex CLI, Claude Code, or Other Agent / existing conversation. For a CLI, select the matching macOS / Linux or PowerShell shell.

  2. Review the scope and confirm.

    Confirm and copy command creates a task authorized to update only README.md in the currently authenticated account’s same-name public repository. Confirm and copy prompt does the same for an existing conversation. Copy draft prompt and Download draft packet do not authorize publishing.

  3. Paste into the right place.

    Paste a CLI command into your computer’s terminal, not the browser address bar. Paste a conversation prompt into an Agent that has authorized GitHub access. The website does not start or control your local programs.

  4. Check the result.

    The Agent should verify its account, preserve your selected projects and entered facts, fill only supported public details, back up an existing README and check its current blob SHA. It must stop on account conflicts or remote changes. Check the returned profile URL, commit URL and backup location.

Automation does not bypass permissions.

Installation, first-time sign-in, tool permissions, branch protection and conflicts may still require your input. If content is too long for a shell argument, use an existing conversation or a draft packet. Review the draft and explicitly authorize publishing afterwards.

See Codex CLI documentation ↗ or Claude Code documentation ↗ for setup.

Option two: copy the README yourself

  1. Replace the example identity and projects.

    Check your username, name, project links and other public details. Manual export does not query your account automatically.

  2. Click Copy README myself.

    Review the resolved source, then copy or download README.md. Fix invalid usernames or unresolved variables before exporting.

  3. Open your same-name public repository.

    For username octocat, use octocat/octocat, not octocat.github.io. Edit the existing repository if it already exists; otherwise create it as public.

  4. Save README.md at the root and commit.

    Keep a backup of your old file. Paste the source into README.md, check GitHub’s preview and commit the change. Visit github.com/your-username to verify it appears.

See GitHub’s profile README guide ↗.

Import a README into forms—or keep its source

  1. Open Import / My templates.

    Load a public GitHub README file URL, choose a UTF-8 .md file under 100 KB, or paste Markdown / HTML. Confirm ownership or permission to reuse it, and retain required attribution.

  2. Review Extraction preview.

    Parsing recognizes common project links, open-source contributions, writing and resources, skills, contact links and custom sections. Work and education are not added to the new forms; the original source is kept. It appends entries to your forms and rebuilds them using the current layout. Names, usernames and bios are only used when you separately enable that option. Review the extracted facts before publishing.

  3. Choose your editing mode.

    Complex layouts, SVG widgets, images and unfamiliar HTML cannot always become structured fields. The original source is kept in My templates and as the latest import backup. Turn parsing off to preserve the original layout and edit its source instead. Custom sections may contain text from otherwise unrecognized sections.

  4. Keep your own backup.

    My templates stores up to 10 imported sources locally, with load, remove and undo-last-removal. Free-edit changes are saved as the current draft; the library retains the imported original. Download important edits before switching templates. Restoring the example preserves My templates.

In Free edit you can import a file directly, insert headings, tables and components, or edit Markdown / HTML. {{DISPLAY_NAME}} and {{GITHUB_LOGIN}} are supported variables. Your Agent resolves them; manual export uses current form values. Extra form entries are not automatically inserted into free-edited source.

The preview supports common Markdown and safe GitHub-style HTML, not every GitHub extension. GitHub controls final typography, sanitization and image caching. Arbitrary CSS, scripts and embedded pages are not supported.

Common questions

Why is Alex Builder shown initially?＋

It is a fictional sample, not the website author or a signed-in account. Import your own public profile, let your Agent fill it, or replace it manually. Old drafts are retained when explicitly edited.

Why is a selected project not clickable?＋

A project needs a repository name or full URL. GitHub-selected repositories always import their full URL. A project with no link is intentionally shown as text; no repository is invented.

Can I use this without a terminal?＋

Yes. Copy the final README and commit it on GitHub, or use a GitHub-capable Agent conversation.

What if parsing misses something?＋

Review the extraction, add or correct fields manually, or keep the original source in Free edit. The parser is deterministic and local; it is not an AI that understands every layout. Never treat inferred structure as verification of someone’s history.

What if an image or clipboard action fails?＋

External images can be unavailable. Retry or use a plain-text layout. If clipboard access fails, select the source in the fallback box or download the file instead.

Does a shared layout URL contain my profile?＋

No. It shares a built-in layout and accent color, not your identity, custom sections or free-edited source. Download a .md file to share complete content, checking for sensitive information first.

Usage, privacy and source permissions

Drafts, forms, import backups and saved templates are kept in this browser’s local storage, not uploaded to our server. They do not sync between devices. Clearing site data deletes them, so download backups first. Use a separate browser profile or private window on shared computers.

Public profile and repository imports contact GitHub’s API; public README URL imports contact GitHub’s raw-content service. External images contact their hosts and may include display text in their URLs. This website does not receive your GitHub token. Enter only information you are willing to make public; never add passwords, tokens, identity documents, home addresses or other sensitive data.

Publicly visible content is not automatically licensed for reuse. Check each source’s license, retain required attribution and verify that imported identity, work, images and contribution data are yours. A gallery’s license does not cover every linked personal README. Importing does not publish your template to this website or verify its truthfulness.

Publishing replaces only the scoped profile README. Existing content should be backed up and remote changes checked before replacement. The website itself performs no GitHub writes. Interface language does not change your personal README text.
