# 轻报销

一个纯前端的报销向导原型。用户上传公司 Excel 模板，再分别上传发票与相关截图，或直接选择包含全部材料的 ZIP 压缩包。浏览器会在本地解压、读取票面、匹配截图，引导用户只补充不确定项，并在逐项确认后按模板导出新的 `.xlsx` 文件。

## 本地运行

在仓库根目录启动静态服务器：

```bash
python3 -m http.server 8080
```

浏览器打开 `http://localhost:8080/reimburse-assistant/`。

## 隐私说明

- 用户选择的模板、发票和截图不会上传到项目仓库或业务服务器。
- 项目仓库不包含任何测试发票、测试截图或从中提取的真实票面数据。
- ZIP 解压、PDF 文本提取、图片 OCR 和 Excel 生成都在浏览器中完成。
- 页面依赖 CDN 加载 PDF.js、Tesseract.js、SheetJS、XlsxPopulate、JSZip 和 Phosphor Icons；首次使用需要联网加载这些程序文件，但票据内容不会作为网络请求发送。
- 刷新或关闭页面会清空本次会话数据。

## 当前边界

- 发票和截图使用两个独立上传入口；电子 PDF 发票优先走文字层提取，图片与截图走浏览器内 OCR。
- 也可以上传 ZIP 压缩包。支持其中包含多层文件夹和 PDF、PNG、JPG、JPEG、WebP 文件，按实际内容区分发票与截图。
- 单个 ZIP 最多 100 个文件，解压后总量最多 80 MB，单个文件最多 20 MB。损坏或不支持的文件会在页面中列出。
- 截图会按发票号、金额和商户等票面事实综合匹配；无法可靠对应时会标记为待核对，不会强行关联。
- OCR 结果必须由用户确认，实际发生日期不会用开票日期自动代填。
- 导出前需要上传公司模板，并逐项确认完整信息。
- 复杂 Excel 功能（宏、外部链接、特殊控件）应在下载后由用户复核。
